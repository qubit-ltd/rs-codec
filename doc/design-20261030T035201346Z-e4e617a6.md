## 当前结构与问题证据

`Codec` 定义单值及生命周期边界；`Transcode*Engine` 管理容量、进度和生命周期；严格 adapter 使用公共 engine。`io` bridge 和 `registry` 是独立可选能力。下游 rs-codec-text 复用 engine/hooks，rs-io-text 与 rs-io-binary 使用 I/O bridge，rs-task 与 rs-model-metadata 使用 value registry，支持保留当前结构。

RC2-001 位于 `src/transcode/engine/transcode_convert_engine.rs`：`drain_decoder_reset` 的约 914 行及 `drain_decoder_finish` 的约 1037 行使用 `(0..value_count).map(...).collect()`。公共输出容量上界度量目标 unit，不能保证内部 `Vec<D::Value>` 的内存布局可表示。评审使用当前源码在项目外编译并运行复现：巨大生命周期 value 上界与零主编码输出上界可让输出规划成功，而临时分配触发 `capacity overflow` panic。该证据确认容量布局溢出；没有通过真实内存耗尽试验验证 allocator 失败。相邻 `src/value/codec_value_decoder.rs` 已使用 `qubit_utils::try_reserve_vec` 并映射 `TranscodeFailure::AllocationFailed`，应沿用此惯例。

RC2-002 位于 `src/codec/codec/codec.rs` 的 `MIN_UNITS_PER_VALUE` 注释，约 155—158 行将该常量称为默认解码 hooks 的除数。实际 `src/transcode/engine/transcode_decode_hooks.rs::max_transcode_output_len` 返回 `input_len`。原因是策略可以消费少于一个合法编码值宽度的非法输入并发出替换值。

RC2-003：`src/lib.rs` 首页概览未解释 `json`、`registry`，而公开导出已包含对应类型；`Cargo.toml` 的 docs.rs 元数据启用 all-features，默认 crate features 为空。README 和用户指南已有相关准确说明，可复用其事实而不改写它们。

RC-009：`benches/transcode.rs` 的 `direct_transcode`、`decode_engine`、旧 `output_window_*` 主要观察计数，部分完整路径仅观察首元素；新增 production-window 路径观察每个写出切片。`benches/README.md` 已注明上次对 LTO 产物的分析无法归属到具体计时闭包，因此仍未确认写入被消除。不能用源代码形状或异常耗时替代机器码证据。

## 方案选择

采用局部修复：两处可失败分配、两处 Rustdoc 更新、一次有条件的 benchmark 核查。另一选择是抽取公共生命周期缓冲 abstraction 或增设 scratch API，但会扩大文件和接口范围；改用 `MaybeUninit` 还会引入 drop 安全与初始化契约工作，均不采用。只补充 panic 文档虽改动更少，却不能实现 RC2-001 的可恢复失败目标，也不采用。

不拆分 stateful/stateless trait，不移除现有 `Default` 约束，不改变 EOF、进度、策略、registry 线程边界，不调整依赖或 CI 配置。

## RC2-001：可恢复的生命周期临时分配

在现有两处分支中保留 `value_count == 0` 快速路径及 codec/hook 调用，替换 `collect()` 为：

```rust
let mut values = Vec::new();
try_reserve_vec(&mut values, value_count)
    .map_err(|_| TranscodeFailure::allocation_failed())?;
values.resize_with(value_count, D::Value::default);
```

reset 分支继续使用局部变量 `reset_values`，finish 分支继续使用 `decoded`；新增单个 `use qubit_utils::try_reserve_vec;`，不为三行重复新增 helper 或模块。预留成功后 `resize_with` 不应再为 Vec 本体扩容。`Default` 实现内部的 panic 或内存分配不属于该修复的保证范围。

错误通过现有 `From<TranscodeFailure>` 转为 `TranscodeConvertError::Failure(TranscodeFailure::AllocationFailed)`。容量规划方法仍返回目标 unit 的原有上界，既不改公开签名，也不新增错误 variant。该处理与 owned decoder 的既有惯例一致。

保持既有执行顺序：reset 已先标记 poisoned 并执行 target reset，然后才准备 source reset 缓冲；finish 已标记 poisoned，可能已排出 pending 值，再准备 source finish 缓冲。本次不移动这些步骤。分配失败后返回结构化错误，converter 保持 `LifecyclePoisoned`；不能将其描述为无副作用或可直接重试同一次 transcode。仅后续成功 reset 才恢复。更新公共 engine 的 reset/finish Errors 描述，说明内部生命周期缓冲的分配失败及上述恢复边界。

新增两项通过公开 `CodecTranscodeConverter` 入口的回归测试：

- source 声明 `MAX_DECODE_RESET_VALUES = usize::MAX`、`Value = u64`，target 主输出上界为零。reset 输出规划仍成功，reset 返回 `AllocationFailed`，随后 finish 返回 `LifecyclePoisoned`。
- source 声明 `MAX_DECODE_FINISH_VALUES = usize::MAX`、reset 上界为零。reset 成功后 finish 返回 `AllocationFailed`，随后 transcode 返回 `LifecyclePoisoned`；再次 reset 能恢复并接受空输入 transcode。

测试值使 Vec 布局必然超过可表示容量，在申请真实巨量内存前失败；不耗尽进程内存，不替换全局 allocator，不依赖操作系统 overcommit。fixture 目标 codec 可声明空 encodable domain，避免用丢弃输入的零宽 encoder 冒充合法的 buffering codec。现有普通生命周期、pending 值和 partition 测试负责正常行为不回归。

## RC2-002：纠正最小输入宽度的说明

保留常量对合法编码值的最小宽度与 unsafe decode 前置条件的定义；删除“默认 hooks 使用该值作为除数”的错误陈述，改为解释：默认 hooks 使用 `input_len`，因为非法输入策略可能消费少于合法值最小宽度的单位并产生替换值。

不把实现改成除法，不改变 `TranscodeDecodeHooks` 的默认行为。文档检查应覆盖 `MIN_UNITS_PER_VALUE > 1` 的策略示例：若逐个非法 unit 产生替换，按合法值宽度相除并不安全。无需新增只检验文本内容的自动化测试。

## RC2-003：完善 crate 首页接入说明

在 `src/lib.rs` 的 Overview 与 Choosing an Abstraction 之间加入英文 `Features` 节：

| Feature | 要说明的事实 |

## RC-009：先核查再决定修复

核查目标为当前工具链和当前 bench profile 下，旧完整路径与旧窗口路径是否执行并保留完整输出写入，以及与新 production-window 路径的比较是否有效。

先构建未修改的当前 bench，记录 Git 基线/dirty 状态、rustc 详细版本、target、CPU、profile、完整构建命令和 Cargo JSON 中的真实 executable 路径。保留最终链接产物、反汇编及分析说明于仓库外证据目录；不能只检查未经历 LTO 的中间 IR，也不能只搜索整个二进制的 `memcpy` 或 SIMD 指令。对每个被质疑闭包关联计时入口、循环、输入读取及完整目标输出写入。

若默认产物无法归属，可用相同优化设置且仅增加行表的辅助构建帮助定位，并记录其与默认构建的差异。辅助构建不能单独证明默认产物的行为；禁止通过关闭 LTO 或降低优化级别得出默认 profile 已通过的结论。

| 核查结果 | 后续动作与完成条件 |
| --- | --- |
| 确认完整写入存在 | 不改 benchmark；更新已有 README 记录工具链范围、方法和结论，不推导跨平台保证 |
| 确认部分或全部输出写入消失 | 只对受影响的测量补充完整输出切片观察；比较路径使用等价观察方式；运行正确性与受影响 benchmark，建立新的测量基线 |
| 证据仍无法归属或不足 | 不修改计时逻辑；README 明确保留待验证状态、缺失证据及下一核查条件，不称缺陷已确认或修复完成 |

确认需要修复时，优先在每次写入后、窗口复用前执行 `black_box(&output[..progress.written()]);`；完整路径使用对应 `written` 长度。保留现有 progress 计数观察。对 safe copy 对照路径也观察等长输出，避免观察粒度不同造成不公平比较。`safe_vs_unchecked` 独立代码生成探针不因统一风格而改动。不得在计时循环内新增分配或全缓冲校验；正确性校验放在计时外。新旧结果须记录观察方式差异，不称为生产代码性能提升。

## 兼容性、影响与迁移

本方案不需要破坏兼容性：所有公开类型、签名、feature、错误 variant 和正常输出保持不变。RC2-001 把内部 Vec 布局/预留失败从 panic/不可恢复分配路径变为已有错误 variant；调用方通过已有框架错误处理分支接收，发生生命周期执行失败后仍须成功 reset。下游无需改代码或依赖版本。

已确认使用点继续保持：rs-codec-text 的 engine/hooks、rs-io-text 与 rs-io-binary 的 I/O bridge，以及 rs-task/rs-model-metadata 的 registry。无需新增 downstream all-features CI。benchmark 若修复，仅影响测量基线解释，不影响运行时 API。
